## 4. How things work

**Stage placement [verified in fallback only].** World Query searches along the gaze, judges hits (normal up, distance and drop-below-eye limits, hits required), places the stage on the table, faces the user. Fallback when no accepted hit arrives. In the Preview every query returned null in three rooms, so the table path has never run. World Query is wearable-only, about 5 Hz, roughly +/-10% depth accuracy (docs, interpolated). Gaze placement puts the stage centroid at the gaze point (`Gaze Depth Ratio` x depth behind the flat edge). Shape: two bezier curves (`Stage Width` 23, `Depth` 29, `Back Handle` 1.0, `Side Handle` 0.8 cm). Snap's comfortable display width is 23 cm at 55 cm (interpolated); the back toys are beyond the 35 to 60 cm near field if the table is 40 cm below the eyes (assumption).

**Sockets.** A socket is one stage-local value per toy, held in `ToyInteraction` (`socketLocal()`), starting at `ToyConfig > Home Position` (stage-local cm: X left/right, Y height, Z back/front; never overwritten at run time). Ring, button, ripple and toy all read it fresh each frame, so moving the stage or a dragged socket moves everything. On release the toy drifts to its socket (fall and slide together, `Drift Speed`, `Drift Lateral Speed`, `Max Drift Seconds` 10), floats with sway and tilt, then settles over `Settle Duration`. Nothing pulls a held toy. Spacing uses the toy's rest footprint plus one fixed disc for ring and button (6.6 cm), only relevant when Enforce Bounds is ON.

**Volume (one door).** `ToyVolume.requestCycle(source, hand)`: per-toy cooldown (0.3 s), same-hand lock (1.0 s), an air-poke is dropped if the pad already counted the same touch, overlapping pads route to the nearest button. Trade-off: a deliberate second tap by the same hand within 1.0 s is ignored.

**Dial button (history §38).** Flat 2 cm disc on the ring's rim, centre at ring radius + button radius + `Button Gap` (1.8 + 1 + 0 = 2.8 cm): it rests on the ring's edge and never goes inside it (gap clamped to >= 0; replaces the old Button Overlap). The button outline (0.2 cm, outside the disc) still reaches over the ring edge unless the gap is raised. Parts: seg1 centre (low), seg2 middle ring (medium), seg3 outer ring (high); boundaries `Button Core End` 0.34, `Mid End` 0.67. Colour = the toy's own `edgeColorOff/Low/Med/High`, re-read about once a second; Off is the toy's colour scaled by `Button Off Brightness` (0 to 100 %, default 100 = unchanged, 0 = black; RGB only, alpha kept; added 2026-11-08, compiles, not looked at in Preview), Low / Med / High use the same kind of slider, `Button Low / Med / High Brightness` (0 to 200 %, default 100 = the toy's exact colour, 200 = double; RGB scaled, alpha kept; replaced the old Brighten blend-to-white values 2026-11-08, compiles, not looked at in Preview). The artist's multiply node (value < 1, before Final Color) sets opacity in `Arc_Mat`; not yet described in the contract below (warns once and falls back to the pad's state colour if unreadable). Press: sinks 0.1 cm, shrinks 3% on a spring. Tap counts on release; a touch that travels 0.8 cm becomes a socket drag.

**Home ring look.** `HomeLookDriver` writes `brightness`, `beatPulse`, `ringRadius`, `padState` and others to `Home_Mat` via `mainPassOverrides` (shared material, never cloned). Off = `Rest Brightness` 0.25; away = dimmed (`Away Dim` 0.7) with a slow pulse; landing flashes `beatPulse`. Colour source is an Inspector choice (`Home Colour Source`), default from the toy material. The toy's material colour read-back at run time is unverified.

**Waves.**
- *Per-socket (default).* `RippleDriver`: up to 3 waves per socket, one per stem hit while the toy is not off, a softer one on landing (`Ripple Landing Strength` 0.5). A hit closer than `Ripple Min Gap` (0.8 s) merges into the newest wave. Script writes numbers only (`rippleProgress{,1,2}`, `rippleStrength{,1,2}`, start/end radius, width, brightness, lighten, fade start, softness, colour); the `Ripple` object is enabled only while a wave lives. Recipe for `Ripple_Mat`: history §35b, with the strength update in §35c.
- *Shared field (IN USE since 2026-11-08; quad, `Wave_Mat` and levels done by the artist).* One big quad (default 60 cm) where up to 8 waves (stage-local start, age, strength) add: `height = strength x exp(-(x/sigma)^2) x cos(2 pi x / Length) / sqrt(1 + Falloff x r / Length)`, picture shows crests only (`max(sum, 0)`), fades at the quad edge. Parameters `wave0..wave7` (u, v, age, strength), `waveShape`, `waveMisc`, `waveColor`, `waveGain`. The GLSL code node and the `Wave_Mat` recipe are in history §36 (not compiled yet). `StageConfig > Wave field > Shared Wave Field` switches it on; key 8 in the Preview starts a test wave. Next ideas: per-wave colour, slope-lit water look, Chladni layer on its own quad, gentle push on toys from `WaveField.heightAt` (hook exists, unused).

**Blob shape (history §21 to §24).** Base `Blob_03` (cube-sphere, 1,649 vertices) is copied per toy with `MeshBuilder.createFromMesh` and deformed once (soft cube, taper, flat bottom, bend, ruffles, lumps, dimples, ridges, welded normals, re-centred to a longest side of 1.0). About 17 to 21 ms per blob at start. Amplitudes are fractions of the longest side (0.02 = 0.8 mm at 4 cm); caps ruffle 0.15, lump 0.15, dimple 0.10, ridge 0.08, final clamp 0.2. Counts up to 10 are clean on this mesh. Lump and dimple size is a fraction of the gap between bumps (default 0.3). A denser mesh was dropped (size budget).

**Size.** `Base Blob Scale` (4 cm) x `Size Multiplier` (0.75 to 1.3) x `Shape Proportions` = `ToyConfig.restScale()`, the only source of settled size. `Fit To Mesh Bounds` (ON for all toys) uses the mesh's real bounds (Y-up in the vertex data; one UV island).

**Audio-reactive motion (history §25).** `OnsetDetector` finds hits (level above a 0.35 s average, spacing 0.1 s). A hit kicks a pop spring (volume kept) and two rocking springs about the blob's base. Comfort limiter caps (squash, bounce, tilt, spring Hz, damping >= overshoot limit). Music Class replaces the 12 music-motion values. Shader Deform (StageConfig and per toy: Follow Stage / On / Off) hands squash, sway, noise and kick to the vertex shader. Stem reading cost about 1 ms/frame on the dev Mac [not measured on device].

**Sync (history §18).** The foundation is the clock. Each `driftCheckInterval` (1 s) a toy stem more than `driftTolerance` (0.02 s) off the foundation fades out, restarts alone with a learned lead, and fades in. A full restart happens only if half the stems slip together or a stem keeps failing. Preview: knock of 80 ms corrected to 0 ms. Natural drift was never reproduced; LowPower playback latency on Specs is untested.

## 6. Shader contracts (artist builds the graphs)
All values are written to the Visual's `mainPassOverrides`; material assets are never edited.
- **`BlobShader_01` (toys).** Script-written: `deformAmount`, `kick`, `squash`, `swayX`, `swayZ`, `noiseStrength`, `noiseScale`, `noiseTime`, `noiseSeed`, `reachBaseY`, `reachHeight`, `lookState` (0 to 3), `audioLevel` (0 to 1), `coreHeat` (0 to 1). `coreHeat` is now the music glow PLUS the alive glow (section 13; no new parameter), and `swayX / swayZ` also carry the lean toward a hand. Material-only: `swayGain`, `noiseGain`, `reachPower`, per-state `bodyOpacity / edgeOpacity / bodyColor / edgeColor / coreRest` (Off, Low, Med, High), `coreColorLow/High`, `coreSize`, `coreSoftness`, `coreGain`, `coreOpacityBoost`, `edgePower`, `rimPulse`. State picker: w1 = clamp(lookState), w2 = clamp(lookState - 1), w3 = clamp(lookState - 2); value = mix(mix(mix(Off, Low, w1), Med, w2), High, w3). Vertex = Surface Position (World) + Transform Vector (object to world, translation OFF) of the displacement. Full table and graph notes: history §25 to §28.
- **`Home_Mat` (ring, additive, depth write off).** `homeColor`, `brightness`, `ringRadius`, `ringSoftness`, `beatPulse`, `padState`. Recipe: history §34.
- **`Arc_Mat` (dial button, additive).** `arcColor`, `discRadius` (fraction of quad half-width; quad = diameter + 2 x Button Glow Margin = 3 cm), `coreEnd`, `midEnd`, `seg1..3` (0..1), `press`. Old `arcRadius / arcThickness / arcSpan / arcGap` are gone.
- **`Ripple_Mat`.** See Waves above and history §35b / §35c.
- **`Wave_Mat`.** See Waves above and history §36.
- **Glitter.** Each toy has `Visual/GliterToy` (VFX Component plus `GlitterDriver`) and its own `Toy_0N_*_Glitter` asset; the asset slot cannot be set by API, so it is assigned by hand.

## 7. Audio findings that still matter
- Stems: median / loudest RMS per 512-sample window: Cello 0.037 / 0.130, Violin 0.022 / 0.117, MixPerc 0.012 / 0.436, PianoMel 0.011 / 0.067, PianoVar 0.0019 / 0.025, SFX 0.0005 / 0.041, Chimes 0.0006 / 0.0145.
- The global `Level Floor` (0.005) is absolute and applied before auto-level, so Chimes always reads 0 (SFX and PianoVar lose quiet notes). Decision: try per-toy `Level Floor` first (about 0.0005 for Chimes, 0.0003 to 0.0005 for PianoVar and SFX). Proposed, NOT built, needs a go-ahead: a floor relative to each stem's own peak.
- Band split (`Band Split Hz`, `Band Mix Kick / Sway / Vfx`): two one-pole low-passes, restarted each read, 512 samples. Weak separation near the split and below about 150 Hz. Better isolation is the next audio task (ask which toys fail, 2 or 3 bands, window length and CPU).
- File audio tracks on Specs are mono; no per-channel API, so a multitrack WAV cannot give separate stems. Published Lens limit is 25 MB.

## 10. Added 2026-11-07
- **Ring On Opacity.** `HomeSettings.onOpacity`; factor = 1 + (opacity - 1) x clamp(state, 0..1), applied to the brightness sent to `Home_Mat`.
- **Push apart.** Each toy carries a small stage-local push (`appliedPush`). `ToyInteraction.onUpdate` removes it first, so every state works on the real position; `StageBounds.updatePush` adds it back in LateUpdate. The needed push comes from the toys' own positions (discs: footprint / 2 + `Push Gap`), 6 relaxation passes; a held toy is never pushed, it pushes; otherwise the push is shared equally. Toys at different heights (|dy| >= mean of heights) ignore each other. A push closes in over `Push Softness`, eases back at `Push Return Speed`. Grabbing a toy keeps it where it is on screen. Toys' Visual colliders are not involved (no physics bodies). [unverified by hand]
- **Sockets are exclusive (2026-11-07).** A toy only ever returns to its own socket (`endGrab`, unchanged). New: `StageBounds.separateFromSockets(toy, desired)` slides a dragged socket off any other placed toy's socket (needed distance = both `socketDiameter()` / 2 + `StageConfig > Sockets > Socket Gap`, default 0.5 cm; 6 passes, returns null if no free spot). `ToyInteraction.moveSocketTo` separates, applies `resolveLanding`, separates again, and leaves the socket where it was if the result still overlaps (crowded stage with Enforce Bounds ON). `socketDiameter()` = `padEquivalentProvider()` (ring + button disc), falling back to the toy footprint. `BoundsToy` gained `socketXZ()` and `socketDiameter()`. With `Toys Return To Sockets` OFF rings follow toys, so nothing to enforce. Gap: `resetSocket()` does not check overlap with another dragged socket. Compiles; NOT tested in Preview.
- **Call home.** `ToyInteraction.callHome()`: held = released toward the socket; away in the air = target set to socket; standing elsewhere = floats home with the normal drift; on its socket = nothing. Dragged sockets are not reset. Subscribed through the reset plumbing as kind `callHome`.
